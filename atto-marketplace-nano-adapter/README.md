# Marketplace Nano wallet adapter

Private local Nano wallet used by Marketplace MCP. It holds native key access, signs Marketplace payments locally, and broadcasts standalone transfers locally, with configured source/index/network/RPC, per-payment/daily limits, durable signed state blocks and exact-candidate recovery. The Marketplace backend receives no customer key material. For x402 it relays only the complete unchanged payment that this wallet authorized.

Use the existing externalTransfers grant for direct Marketplace requirement payments. NOMS `payment evidence` proofs require that grant and the exact configured origin/audience/network/sender frame. Other controller purposes retain their explicit grants/typed terminal approvals; ordinary Ed25519 or native transaction signing is not NOMS. A separately configured controller directory is used for identity purposes, while payment evidence uses the actual sending wallet.

The adapter retains OS-protected shared BIP39 recovery with versioned Nano SLIP-0010 derivation or explicit native seed imports, immutable source/journal ownership, user-only permissions, trusted network/genesis checks, local signature/work validation, unknown-source fencing and byte-identical publication retries. Source, RPC and work-provider changes must preserve original journals. Never create a replacement SEND merely because a response timed out.

`transfer.send` / `transfer.status`, native identity/balance, receivables/receive and NOMS controller proofs are reached through the typed private wallet host. Shared Marketplace requirements are independently verified by backend status; local wallet state alone never creates entitlement or marks a milestone paid. See [Marketplace reference](../docs/marketplace-mcp-reference.md). This package is an implementation dependency of the installed Marketplace client; HTTP consumers can use their own compatible local Nano/NOMS wallet.

Private `payment.prepare`, `payment.authorize`, and `payment.status` operations share the ordinary native transfer journal, account lane and spending allowance. Preparation saves the full signed state SEND with valid work; authorization saves one immutable x402 header and its exact NOMS proof. None of these wallet operations broadcasts. Market submits the saved block, and read-only native reconciliation recognizes confirmed SEND without waiting for recipient RECEIVE. Generic transfer commands cannot replace or publish a relay operation under its saved request ID.

The supported x402 profile is the unmerged Nano proposal3432 at `96f65c29`: exact XNO signed state SEND, string raw balance, destination link plus `link_as_account`, and wallet-supplied valid work. Marketplace binding is a required application extension. Unknown outcomes retain the original offer, candidate, identifier and proof even after expiry; no new candidate is signed.
